# Design: 새 피그마 완성 디자인 전면 적용

## Context

- 동기·범위는 proposal.md, 요구사항은 specs/ 델타. PM 결정과 비교 기준의 원본은 `planning/prompts/design-v2-2026-10-09.md`(A-2 결정 1~7, A-3 화면·비교 기준, B 노드 지도).
- 새 기준 피그마: fileKey `U3GaTLJGAbLj5qgTTJiodv`, '디자인' 페이지 `180:5325`, 프레임 402×874. 화면 흐름도 `180:8460`, 버튼별 이동표 `180:9005`.
- 지금 코드(2026-10-09, `b8d7e2e`)는 옛 와이어프레임 구조다: `/app`(홈), `/app/mic`, `/app/ask`(AskScreen + askFlow), `/app/cards`, `/app/cards/[id]`, `/parent`. 앱 틀 390px, Noto Sans KR, 회색 토큰. 저장 키는 `moya.cards.v1`, `moya.pending.v1`.
- 바뀌지 않는 제약: 외부 API는 STT 하나(지금 mock), 음성 출력은 `speechSynthesis`, 설명·예문은 `src/data` 검수 데이터만, 아이 음성 원본은 저장 안 함, `src/lib/pronunciation`은 외부 API 없는 순수 함수, 새 의존성은 확인 후.

## Goals / Non-Goals

**Goals:**
- 402×812에서 아이·보호자 화면 56장(베타 8장 제외)을 피그마와 ±1px로 맞추고, 이동표대로 이동하게 한다.
- 새 흐름을 하나의 상태 기계와 기기 저장소로 구현해 테스트로 지킨다.
- 마이크 없이도(폴백) 시연 시나리오를 끝까지 진행할 수 있게 유지한다.

**Non-Goals:**
- ④ 베타 8장(4-1~4-6), 복습 상태 바꾸기, 주간 리포트 숫자 계산의 정확성, 구독.
- 실제 카카오·서버 계정·메일 발송, 계정 간 기기 동기화.
- 피그마 프로토타입의 자동 넘김 시간을 실제 흐름에 쓰기(mock STT일 때만).
- 모션(그룹 13)은 범위를 그때 확인한다. 이번에는 정적 화면과 이동만.

## Decisions

### Decision: 아이 묻기 흐름은 `/app` 한 주소 + 상태 기계
2-1에서 마이크를 누르면 같은 자리(헤더·모야·탭 유지)에서 듣는 중이 되므로, 2-1~2-14와 E-1·E-2를 `/app`의 askFlow 상태로 둔다. 녹음·인식 중인 비동기 작업과 마이크 스트림을 한 컴포넌트에서 관리할 수 있다. 대안(화면마다 주소)은 새로고침·뒤로 가기에는 유리하지만 녹음 중 이동 시 정리가 복잡하고, 피그마에도 아이 묻기 화면에는 뒤로 버튼이 없다. 새로고침하면 2-1로 돌아간다.

### Decision: askFlow를 새 흐름으로 다시 쓴다
상태: `idle → listening → thinking → confirm | unknown | retry | blocked | networkError`, `confirm → explaining | context`, `context → choose`, `choose → explaining | unknown`, `explaining → collected`, `micOff`. 액션 예: `startListening`, `stopListening`, `recognized(transcripts)`, `recognitionFailed(network|empty)`, `answerYes`, `answerNo`, `pickContext(ctx|null)`, `pickCandidate`, `noneOfThese`, `understood`, `cardCollected(isNew, missionCompleted)`, `micUnavailable`, `goHome`. 순수 reducer로 두고 테스트로 지킨다. 저장·별 주기는 지금처럼 reducer 밖에서 하고 결과를 액션으로 알린다. `review`·`open*`·`showRetryGuide`·`back`·`retryCount`는 없앤다.
- 자동 넘김: 녹음 끝 → thinking, 인식 끝 → 결과. mock STT일 때만 2.5초/1.5초를 흉내 낸다. 2-13 → 2-14는 실제로도 1.5초.
- 네트워크 오류는 서비스 어댑터에서 한 번 다시 시도한 뒤 `recognitionFailed(network)`.

### Decision: 후보 순서 — 알려 준 단어 → 거리 → 들은 곳 → 데이터 순
`src/lib/pronunciation`은 순수 함수로 유지한다. 보호자가 알려 준 연결(`Record<들은 말, wordEntryId>`)은 저장소에서 읽어 `inferWord`의 입력으로 넘긴다(함수 안에서 저장소를 읽지 않음). 연결이 있으면 그 단어를 거리 0의 첫 후보로 넣고 나머지는 기존 규칙을 따른다. 2-5에서 고른 들은 곳은 남겨 둔 `orderByContext`로 다시 정렬한다. 2-4는 첫 후보, 2-6은 모든 후보(최대 3, 2-4에서 아니라고 한 단어 포함)다. 후보가 1개뿐이어도 2-6에 1장을 보여준다(거리 기준을 넓히지 않는다). 후보 수에 따른 `CandidateResult` 종류(confirm/choose)는 화면 분기에 쓰지 않는다.
- 대안: 2-6에서 2-4의 단어를 빼기 → 피그마 2-6에 2-4의 저금통이 있어서 따르지 않음.

### Decision: 들은 곳 값 바꾸기
`HeardContext`를 피그마 5개로 바꾼다: `home`(집), `school`(유치원·학교), `tv`(TV·영상), `book`(책), `outside`(밖에서). 옛 값 `adult`는 없앤다. 옛 카드의 `heardContext: "adult"`는 읽을 때 무시한다. 단어 데이터의 `contextTags`도 이 값으로 다시 단다(그룹 1).

### Decision: 단어 데이터 필드
`WordEntry`에 `image`(public 그림 경로), `bubbleExplanation`(2-9 말풍선 설명, 예: "저금통은 돈을 모아 두는 통이야. 동전을 쏙 넣어서 모아!")를 더한다. `kidExplanation`은 카드 설명("돈을 모아 두는 통이야. 동전을 쏙 넣어서 모아."), `example`은 카드 예문(앞의 "예) "는 화면에서 붙임), `hint`는 2-4·2-6 힌트("돈을 모아 두는 통")로 쓴다. `english`는 남기되 화면에 쓰지 않는다. mock 단어는 피그마 시연 단어(저금통·저울·조금·우산·편의점·나비·무지개·씨앗·달팽이 등)로 바꾸고, 글자는 피그마 문구 그대로 넣는다(검수 전 표시 유지).

### Decision: 기기 저장 키
모두 localStorage, 키마다 버전, 읽기 실패·손상 시 기본값, 쓰기 실패는 흐름을 막지 않는다(기존 방식).

### Decision: 가짜 가입·잠금
- 이메일 로그인은 저장된 이메일과 같은지만 본다. 계정 비밀번호는 저장하지 않는다(가짜 계정에 실제 비밀번호를 평문으로 남기지 않기 위해). 카카오 버튼은 `method: "kakao"`로 같은 흐름.
- 보호자 4자리는 아이가 보호자 화면에 들어가지 못하게 하는 기기 잠금이고 보안 수단이 아니다. 평문 저장, 화면 문구는 피그마 그대로.
- 잠금 해제는 메모리(React 상태)에만 둔다. 새로고침하거나 [아이 모드로 돌아가기]를 누르면 다시 잠긴다.
- 5-1b는 아무것도 보내지 않고 5-1로 돌아간다. 비밀번호를 잊으면 이 기기에서 되찾을 방법이 없다(Risks).

### Decision: 별·미션·로켓 계산
- 미션은 "오늘 물어서 새로 모은 카드 수"(오늘의 단어 카드·이미 있던 단어 제외). 3이 되는 순간 하루 한 번 별 +3과 그날 로켓 도장.
- 연속 학습 = 오늘(또는 어제)까지 이어진 로켓 도장 일수. 이번 주 도장은 월~일. "모야랑 ○일째"는 프로필 만든 날부터 센다.
- 헤더 미션 별 칸 = `min(collectedCount, 3)`.

### Decision: 오늘의 단어 고르기
지구 사전에 없는 검수 단어 중 날짜 문자열로 정해지는 순서(간단한 해시)로 하나를 고르고 `moya.today.v1`에 그날 값으로 고정한다. 외부 데이터·랜덤 시드 없음.

### Decision: '녹음 듣기'와 '내가 말한 소리'는 인식 글자 TTS
음성 원본을 저장하지 않으므로(결정 2) 2-8·2-10·3-2의 '내가 말한 소리' 칩과 5-3의 스피커는 인식된 글자를 speechSynthesis로 읽는다. 5-3 카드의 "· 녹음 듣기" 글자만 숨긴다. 칩·스피커 모양은 피그마 그대로.

### Decision: 폴백(글자 입력·예시 버튼) 자리
피그마에 없는 화면이다. 마이크를 쓸 수 없을 때만 2-1 마이크 아래와 E-2 버튼 위에 글자 입력칸 + 예시 버튼을 공통 부품(입력칸·보조 버튼) 스타일로 둔다. 2-7 [글자 카드로 고를래]는 후보가 없으면 같은 폴백을 보여준다. 정확한 배치는 그룹 6·11에서 PM에게 보여주고 정한다.

### Decision: 스타일·글꼴·에셋
- 토큰은 피그마 변수(`get_variable_defs`)를 `globals.css` `@theme`로 옮긴다. 주요 값: 크림 `#fdf9ed`, 진한 글자 `#241f48`, 보통 글자 `#6f6a8c`, 라임 `#d2ec7c`, 코랄 `#ff6b5b`, 연보라 선 `#d9d0ff`, 흰 면 `#ffffff`, 보라 `#7b61f8`.
- 글꼴: Jua(말풍선·제목, next/font/google), NanumSquareRound ExtraBold(하단 탭, next/font/local — 파일 출처·라이선스는 그룹 1에서 확인받은 뒤), Noto Sans KR(본문, 유지). Inter는 쓰지 않는다.
- 에셋: 모야 표정·단어 그림·아이콘을 `download_assets`로 받아 즉시 `public/`에 저장한다. 코드에 피그마 임시 URL을 남기지 않는다. 파일 이름 규칙은 그룹 1에서 표로 정한다.
- 상태바(62px)·홈 인디케이터는 그리지 않는다. 하단 탭바 아래 46px는 `env(safe-area-inset-bottom)`과 피그마 값 중 큰 쪽.

### Decision: 피그마와 비교하는 방법
새 패키지 없이 headless Chrome으로 402×812 스크린샷을 찍고, 피그마 `get_screenshot`(위 62px 잘라 냄)과 나란히 놓아 본다. 위치는 DOM 좌표와 피그마 `get_metadata` 좌표(y − 62)를 비교해 ±1px. 글자 렌더링 차이는 표로 보고한다. 비교 이미지는 커밋하지 않는 임시 폴더에 둔다. 픽셀 비교 도구가 필요하면 설치 전에 묻는다.

### Decision: 데모 시드 데이터
피그마 화면(지구 사전 6장, 별 24개, 연속 3일 등)과 겹쳐 보려면 저장 데이터가 피그마와 같아야 한다. 개발·시연 때만 쓰는 시드 함수로 피그마 상태를 이 기기 저장소에 넣는다(배포 화면에 버튼으로 노출하지 않음, 방법은 그룹 3에서 정함). 실제 첫 사용은 빈 상태에서 시작한다.

## Risks / Trade-offs

- [피그마 시연 단어가 실제 발음 거리로 재현되지 않을 수 있음(예: 한 질문에서 저금통·저울·조금이 모두 후보)] → 그룹 1에서 mock 단어·STT mock 순서를 거리 계산으로 검증하고, 안 되면 mock STT가 인식 후보를 여러 개 돌려주게 해 시연을 맞춘다. 거리 기준값은 바꾸지 않는다.
- [NanumSquareRound 파일 라이선스·용량] → 그룹 1에서 출처·라이선스·파일 목록을 먼저 확인받고, 안 되면 탭 글꼴만 대체안 보고.
- [402px 기준으로 맞추면 375px에서 좁아짐] → 가로 넘침·잘림 없음을 화면마다 확인, 간격은 비율이 아니라 최소값으로 줄인다.
- [보호자 비밀번호 평문, 이메일만 맞으면 로그인] → MVP mock이라는 것을 문서에 남기고, 실제 계정은 베타.
- [보호자 비밀번호를 잊으면 복구 불가] → 시연 기기에는 알려진 번호를 쓴다. 필요하면 개발용 초기화 방법을 그룹 3에서 정한다.
