# Design: 모야 MVP — 묻기 → 되묻기 → 단어 카드

## Context

- 현재 상태: Next.js 16 App Router 프로젝트 뼈대만 있다. `/`, `/app`, `/app/cards`, `/parent`는 제목(h1)만 있는 빈 화면이고, `src/lib/*`, `src/data`, `src/types`, `tests/`는 빈 폴더다. 테스트 도구는 없다.
- 상세 설계 원본: planning/md-design/04_TECHNICAL_DESIGN.md (route, source structure, data model, state, storage). 화면·컴포넌트는 03_UX_UI_SPEC.md, 오늘 범위·QA는 05_DELIVERY_PLAN.md. 이 문서는 그중 구현 결정과 이유만 정리한다.
- 제약: openspec/config.yaml의 context 참고 (외부 API는 STT 하나, 검수 데이터만으로 설명, 음성 원본 미저장, 새 의존성은 확인 후).

## Goals / Non-Goals

**Goals:**
- 외부 API 없이(텍스트 입력 + mock 데이터) 묻기 → 되묻기 → 카드 저장이 먼저 끝까지 동작하고, 그 위에 음성 입출력을 붙인다.
- 되묻기 로직을 UI·네트워크와 분리된 순수 함수로 만들어, 녹음 테스트(10/16~22) 결과로 역규칙·임계값만 바꿔 보정할 수 있게 한다.
- 마이크가 실패해도 예시 버튼으로 시연 장면을 그대로 재현한다.

**Non-Goals:**
- 반복 학습(F4), 부모 리포트(F5) — 베타. `/parent`는 빈 화면 유지
- LLM 실시간 설명, LLM 재순위, 사전 API — 베타
- 결제·구독, 로그인, 서버 DB — BE 합류 후 결정
- 모야 캐릭터 애니메이션과 비주얼 스타일 — Figma 시안 확정 후. 이번에는 정적 자리 + 상태 글자
- 단어 데이터 50~100개의 작성·검수 작업 자체 — 코드 밖 작업(05 §6 체크리스트). 이 change는 데이터 형식과 mock 10개까지만 다룬다

## Decisions

### Decision: `/app/ask` 한 페이지 + useReducer 상태 기계
- 선택: 묻기 흐름(S1~S6, E1, E2)을 `/app/ask` 한 페이지에서 상태로 전환한다. 처음에는 `/app`에 두었으나 Figma 와이어프레임 반영으로 `/app`은 아이 모드 홈이 됐다(아래 "Figma 와이어프레임 반영"). 상태와 화면 대응은 04 §4 표를 따른다.
- 이유: 단계 사이에 후보·인식 텍스트·다시 말하기 횟수를 넘겨야 하고, 뒤로 가기로 흐름이 꼬이지 않게 한다. reducer는 순수 함수라 단위 테스트할 수 있다.
- 대안: 단계별 라우트(`/app/confirm` 등) — URL 상태 전달이 번거롭고 새로고침 시 중간 상태가 깨져 택하지 않음. 상태 관리 라이브러리 — 화면 하나 규모라 불필요.

### Decision: Figma 와이어프레임 반영 (2026-10-04)
- 기준: Figma 와이어프레임 Section 1(화면 10개, node 1271-481). 디자인(색·폰트·캐릭터)은 입히지 않고 화면 구성·이동·문구만 맞춘다. 이미지 자리는 "모야 캐릭터 자리"처럼 이름 붙인 점선 박스로 둔다. 기존 로직(askFlow reducer, pronunciation, storage, src/data)은 그대로 쓴다.
- 라우트:

| 경로 | 화면 | 비고 |
|---|---|---|
| /app | S9 아이 모드 홈 | 하단 탭 |
| /app/mic | S10 마이크 권한 안내 | |
| /app/ask | S1~S6, E1, E2 묻기 흐름 | 상태 기계 |
| /app/cards | S7 단어 카드 목록 | 하단 탭 |
| /app/cards/[id] | S11 단어 카드 상세 | S5 카드 모양 재사용 |
| /parent | S8 보호자 | 빈 화면 유지 (베타) |
| / | S0 랜딩 | 11.1에서 |

- 화면 매핑 (Figma → 상태):

| Figma | 화면 | 상태(04 §4) |
|---|---|---|
| 1 아이 모드 홈 | S9 | — |
| 2 마이크 권한 안내 | S10 | — |
| 3 음성 녹음 | S1·S2 | idle, listening, thinking |
| 4 다시 말하기 안내 | E2 | sttFailed |
| 5 되묻기 | (별도 단계 없음, D1) | — |
| 6 단어 확인 질문 | S3 | confirm |
| 7 후보 카드 선택 | S4 | context → choose |
| 8 단어 카드 | S5 | explaining, saved |
| 9 물어볼 단어 안내 | S6 | unknown |
| 10 단어 카드 목록 | S7 | — |

- D1 되묻기 화면은 별도 단계로 만들지 않고, 그 안내 문구("모야가 잘 못 들었어요. 아래 단어 중에 골라봐요!")만 후보 카드 선택 화면에 쓴다. 이유: 같은 후보를 두 번 보여주게 되고, 아이 화면은 한 화면에 주요 행동 하나가 원칙이다.
- D2 맥락 질문("어디서 들었어?" + 상황 버튼)은 Figma에 없지만 후보 카드 선택 앞 단계로 유지한다. 이유: 발표 차별점인 '맥락 기반 단어 유추'의 핵심 장면이다.
- D3 후보 카드마다 [들어보기]와 [이거야!]를 둘 다 둔다(Figma에는 [들어보기]만 있어 고를 방법이 없음). 후보는 MAX_CANDIDATES=3 유지(Figma 예시는 4개).
- D4 카드는 [내 단어장에 저장하기]를 눌러야 저장한다(이전: S5 진입 시 자동 저장). 저장 후 버튼은 "저장했어!"로 바뀌고 비활성. 목록에서 연 상세에서는 버튼을 숨긴다. 물어볼 단어는 지금처럼 자동 저장한다. 이유: Figma 흐름을 따르고, 아이가 저장을 직접 고르게 한다.
- D5 영어 표기(Figma의 "rainbow")는 WordEntry에 필드가 없어 표시하지 않는다 [나중].
- D6 이미지는 전부 점선 자리 박스로 두고, 그림 데이터는 추가하지 않는다.
- 구현 결정 (문서에 없어서 정함):
  - E2 [다시 녹음하기]는 새 액션 `retry`로 처리한다. sttFailed·micDenied에서 idle로 가되 retryCount를 유지한다. `restart`는 retryCount를 0으로 되돌려 되묻기 횟수 제한이 풀리기 때문이다.
  - 카드 저장에 실패하면 "저장하지 못했어" 안내를 보이고 버튼을 다시 누를 수 있게 둔다.
  - 카드 상세 id는 저장된 `WordCard.id`다. 없는 id면 자동 이동하지 않고 "그 카드를 찾을 수 없어" 안내 + [단어 카드 목록으로]를 보여준다. 상세의 "<"는 목록으로 간다.
  - 카드 상세(S11)에는 단어 아래 작은 글씨로 처음 물은 말("처음엔 '두박'이라고 물어봤어")을 보여준다. 묻기 흐름의 S5에는 보이지 않는다.
  - 묻기 대기(S1)의 [단어장] 버튼은 뺀다. Figma에 없고, "<"로 홈에 가면 하단 탭이 있다.
  - 부적절 단어(blocked) 화면은 Figma에 없지만 그대로 두고 [또 물어보기], [단어 카드 목록]을 유지한다.
  - 묻기 흐름의 "<"는 흐름을 restart하고 홈(/app)으로 간다. 권한 안내의 "<"도 홈으로 간다.
  - 하단 탭 [홈] [단어 카드] [보호자]는 홈과 단어 카드 목록에만 둔다.
  - 와이어프레임의 밑줄 링크(녹음 화면 "다시 말하기", 되묻기 화면 "단어 확인 질문 보기·물어볼 단어 안내 보기")는 화면 연결 표시로 보고 버튼으로 만들지 않는다. 분기는 인식 결과로 자동 결정한다.
  - 1단계(마이크 연결 전)에는 [권한 허용하기]도 [나중에 할래]처럼 /app/ask로 간다. [녹음 시작]은 비활성 + "마이크는 곧 연결돼요", [들어보기]·[음성 재생]은 자리만 둔다. 실제 권한 요청은 작업 10.4, 소리는 9.1에서 붙인다.
  - Figma MCP는 참고만 하고, 문구는 이 결정의 화면 명세를 기준으로 쓴다.
- Figma와 다르게 한 부분:
  - 맥락 질문 단계 추가 (D2), 되묻기 화면 생략 (D1), 후보 카드에 [이거야!] 추가·후보 최대 3개 (D3), 영어 표기 생략 (D5)
  - **단어 카드(S5)와 물어볼 단어 안내(S6)에 보조 버튼 [또 물어보기]를 둔다.** 누르면 restart 후 묻기 화면(S1)으로 간다. 이유: 시연 때 장면을 연속으로 보여줘야 해서 시연 안정성을 우선한다(Figma대로면 "<" → 홈 → 물어보기 → 권한 안내 → 묻기를 거쳐야 한다).
  - 묻기 화면(S1)·E1·E2에 텍스트 입력, 예시 버튼, 저장·전송 안내를 유지한다 (CLAUDE.md 폴백 규칙)
  - 부적절 단어(blocked) 화면 유지
  - 카드 상세(S11)에 처음 물은 말 표시 (Figma 단어 카드에 없음)
  - 홈의 "오늘 복습할 단어가 있어요" 배너, 목록의 학습 상태 Select·필터 칩(새 단어/복습 중/완료)은 반복 학습(베타)이라 만들지 않는다. [복습하기] 타일은 "베타" 표시 + 비활성
- 대안: Figma의 되묻기 화면을 별도 단계로 구현 — D1 이유로 택하지 않음. 카드 자동 저장 유지 — Figma와 달라 택하지 않음.

### Decision: 되묻기 = 역규칙 변형 + 자모 편집거리
- 선택: 대상 단어를 초성·중성·종성 자모로 나누고, R1(ㅅ·ㅆ↔ㄷ·ㄸ)·R3(된소리·거센소리↔예사소리) 초성 대치로 변형 목록을 만든 뒤, 변형마다 단어 데이터와 자모 레벤슈타인 거리를 재서 최솟값을 그 단어의 거리로 쓴다. R2(받침 생략)는 별도 변형 없이 종성 삽입 비용 1로 처리한다(잠정). 임계값 2, 최대 후보 3, 다시 말하기 1회는 설정 파일 한 곳에 둔다.
- 이유: 외부 의존 없이 설명 가능하고, 녹음 테스트 결과를 규칙 표와 설정값만 바꿔 반영할 수 있다. mock 10개로 계산해 보니 분기 3가지가 의도대로 나온다(05 §4).
- 대안: 음소 유사도 가중치 행렬 — 근거 데이터(녹음 테스트) 전이라 보류. 발음 변환 라이브러리 — 새 의존성이라 보류.

### Decision: 상황 단서는 동점 정렬로만 쓴다
- 선택: 거리 순으로 정렬하되, 거리가 같은 후보 사이에서만 고른 상황 태그를 가진 단어를 앞으로 보낸다. 상황 값은 tv / book / adult / school 네 가지(잠정)이며, [모르겠어]는 값 없음이다.
- 이유: 발음 근거가 상황 근거보다 강하다. 동점 정렬만으로도 시연 장면(가바 → [TV] → 가발 먼저)이 성립하고, 발음상 더 먼 단어가 상황 때문에 앞서는 일이 없다.
- 대안: 거리와 상황을 합친 점수 — 가중치 근거가 없어 보류. LLM 재순위 — 베타.

### Decision: 단어 데이터는 소스 안의 TypeScript 모듈
- 선택: 단어 데이터(`WordEntry[]`, 04 §3), 역규칙 표, 예시 질문 문장, 부적절 단어 목록을 `src/data`에 TS 모듈로 둔다. mock 데이터 파일 맨 위에 "mock, 검수 전"을 명시하고, 녹음 테스트 단어 10개가 완성되면 교체한다.
- 이유: 50~100개 규모는 번들에 넣어도 작고, 네트워크 없이 동작해 시연에 안전하다. 타입 검사로 필드 누락을 잡는다.
- 대안: JSON + 서버 API — 지금 규모에 불필요. 외부 사전 — 베타.

### Decision: 저장은 localStorage, 버전 키, 실패 무시
- 선택: `moya.cards.v1`, `moya.pending.v1` 키에 JSON 배열로 저장한다. 읽기·쓰기를 try/catch로 감싸고, 실패하거나 형식이 깨지면 빈 목록으로 처리한다. 저장소 접근은 주입 가능한 인터페이스로 감싸 Node 테스트에서 가짜 저장소를 쓴다.
- 이유: 로그인·서버 DB 없이 같은 기기에서 유지된다. 시크릿 모드 등에서 저장이 막혀도 흐름은 계속된다(word-cards 스펙).
- 대안: IndexedDB — 데이터가 작아 불필요.

### Decision: STT는 서버 라우트 + 어댑터, 응답은 후보 배열
- 선택: 클라이언트가 녹음한 오디오를 `POST /api/stt`로 보내고, 서버의 STT 어댑터가 `{ transcripts: string[] }`(확률 높은 순)을 돌려준다. 어댑터는 같은 인터페이스로 mock과 실제 구현을 두고 환경변수로 고른다. API 키는 `.env.local`의 `STT_API_KEY`로 서버에서만 읽는다.
- 이유: 키 보호(NFR-03), n-best 대응(FR-01), STT 선정 전에도 mock으로 흐름 확인.
- 대안: 브라우저 내장 음성인식 — 비교 후보로 남긴다(04 §1). 선정되면 클라이언트 어댑터로 붙이고 같은 `transcripts` 형태로 맞춘다. 서버 라우트는 그 경우 쓰지 않는다.

### Decision: 녹음은 브라우저 MediaRecorder, 음성 출력은 speechSynthesis
- 선택: 녹음은 MediaRecorder(새 패키지 없음), 음성 출력은 `speechSynthesis`(ko-KR)를 얇게 감싼 래퍼로 쓴다. 미지원이면 래퍼가 아무것도 하지 않고 글자만 남는다.
- 이유: 외부 API·패키지 없이 동작한다. 음성 원본은 메모리에서 전송 후 버린다(NFR-04).
- 대안: 외부 TTS — 해커톤 범위 밖으로 결정됨.

### Decision: 단위 테스트는 Node 내장 테스트 러너
- 선택: `node --test`로 `tests/**/*.test.ts`를 실행한다(Node 26은 TS 타입을 그대로 지워 실행). 테스트 대상 모듈(`src/lib/pronunciation`, `src/lib/storage`, reducer)은 서로를 `.ts` 확장자가 붙은 상대 경로로 import하고, tsconfig에 `allowImportingTsExtensions`를 켠다(이미 `noEmit`). `package.json`에 `test` 스크립트를 추가한다.
- 이유: 새 의존성 없이 순수 로직을 테스트할 수 있다(scratchpad에서 동작 확인).
- 대안: Vitest·Jest — 새 의존성이라 확인 전에는 쓰지 않음. 컴포넌트 테스트가 필요해지면 그때 제안한다.

## Risks / Trade-offs

- [STT가 서툰 발음을 실제 단어로 교정해 돌려줌 (추정)] → n-best 전부를 입력으로 쓰고, 녹음 테스트에서 STT 3종을 같은 녹음으로 비교해 고른다(04 §1). 그래도 부족하면 '교정된 단어 → 원래 단어' 쌍을 역규칙 표에 추가한다.
- [iOS Safari에서 MediaRecorder 출력 형식이 다름 (추정)] → STT 선정 기준에 해당 형식 지원을 넣고, 실기기에서 확인한다. 실패 시 E2와 예시 버튼으로 진행.

## Migration Plan

첫 배포라 기존 데이터 이전은 없다. 저장 키에 `v1`을 붙여 두어, 형식이 바뀌면 새 키로 옮기거나 버릴 수 있게 한다. 배포 환경은 미정이다.

- 구현 중 정한 잠정 해석 (녹음 테스트 후 보정):
  - R1 대치 쌍 — 기본 가정: "ㅅ·ㅆ ↔ ㄷ·ㄸ"를 ㅅ↔ㄷ, ㅅ↔ㄸ, ㅆ↔ㄷ, ㅆ↔ㄸ 네 쌍의 양방향 초성 대치로 본다 (`src/data/rules.ts`)
  - R3 대치 범위 — 기본 가정: 같은 계열(ㄱ·ㄲ·ㅋ / ㄷ·ㄸ·ㅌ / ㅂ·ㅃ·ㅍ / ㅈ·ㅉ·ㅊ) 안에서는 어느 쪽으로든 서로 대치한다
  - 받침의 거리 계산 — 기본 가정: 초성 ㅇ과 받침 ㅇ은 서로 다른 자모로 센다. 받침이 없으면 자모를 세지 않으므로, 받침 생략(R2)은 거리 1이 된다 (`distance.ts`)
  - 대상 단어 추출 범위 — 기본 가정: "뭐야" 바로 앞의 공백 없는 한 덩어리만 꺼낸다. 예: "저 공룡이 뭐야" → 공룡 (`extract.ts`)
  - 같은 거리 후보의 순서 — 기본 가정: 단어 데이터에 들어 있는 순서를 따른다 (`candidates.ts`). 예: 상황 없이 "가바"를 물으면 가방이 가발보다 먼저 나온다. 데이터 순서를 바꾸면 결과도 바뀐다. 이 순서는 MAX_CANDIDATES로 자를 때 어느 단어가 빠지는지에도 영향을 준다. 대안: 04 데이터 모델(`WordEntry`)에는 빈도·난이도 필드가 지금 없다. 아이가 많이 듣는 정도(빈도)나 난이도 필드를 추가하면 그 값으로 정렬할 수 있다
- 단어장(S7) 표시 — 스펙에 없음. 현재 동작: 카드와 물어볼 단어 모두 최근 저장한 것이 위로 온다. Figma 와이어프레임 반영 후 목록은 2열 그리드(그림 자리 + 단어)이고, 쉬운 설명·예문·들은 상황은 카드 상세(/app/cards/[id])에서 보여준다. 상세에는 단어 아래 작은 글씨로 처음 물은 말("처음엔 '두박'이라고 물어봤어")을 보여준다. 이유: 서툴게 물어도 찾아준다는 핵심 장면이 단어장에도 남아야 한다(Figma 카드에는 없는 요소). 같은 단어를 다시 물으면 카드가 한 장 더 쌓인다(중복 제거 없음). 중복을 합칠지, 반복 학습(베타)에서 "다시 물어본 횟수"로 쓸지 정해야 한다
- 그룹 12 구현 중 정한 화면 세부 (Figma·스펙에 없음, 디자인 작업에서 바뀔 수 있음):
  - "<"는 아이콘만 있는 버튼 금지(NFR-08) 때문에 "< 홈", "< 목록"처럼 짧은 글자를 붙인다
  - 단어 카드(S5) 화면 제목(h1)은 "단어 카드"이고, 모야 대사 영역 대신 카드 안의 "○○이 뭐야?"를 보여준다. 조사(이/가, 이라고/라고)는 마지막 글자의 받침으로 고른다
  - 확인 질문(S3)은 모야 대사("수박 말하는 거야? <힌트>!") 아래에 단어 그림 자리·단어·힌트를 한 번 더 보여준다 (Figma 6 구성 유지)
  - 저장하면 상태가 바뀌어 다른 화면 전환처럼 제목으로 포커스가 옮겨진다. 스크린 리더에는 "단어장에 저장했어!"를 따로 알린다
  - [녹음 시작]·[들어보기]·[음성 재생]은 비활성(흐리게)으로 둔다. [복습하기] 타일도 비활성 + "베타 · 곧 열려요"
  - 목록 카드에는 들은 상황·처음 물은 말을 빼고 그림 자리 + 단어만 둔다 (상세에서 보여줌)
  - /parent에는 돌아가는 버튼이 없다 (빈 화면 유지 결정). 브라우저 뒤로 가기로만 돌아온다 — 보호자 화면 작업 때 정한다
- 지시어만 있는 질문("이게 뭐야", "저거 뭐야", "이건 뭐야") 처리 — 스펙에 없음. 현재 동작: "이게"·"저거"·"이건"을 대상 단어로 꺼낸다. 그래서 후보 찾기로 넘어가고, 후보가 없으면 물어볼 단어로 저장된다. E2로 보낼지, "어떤 말이 궁금해?"처럼 다시 물을지 정해야 한다 (녹음 테스트 후 보정)
- 부적절 단어 판별 방식 — 스펙에 없음. 현재 동작: 꺼낸 대상 단어가 목록 단어와 정확히 같을 때만 막는다(자모 거리·역규칙으로 비슷한 발음은 막지 않음). 인식 후보가 여러 개면 하나라도 걸리면 막는다. 막은 단어는 상태에도 남기지 않고, 안내 화면 제목·대사는 "엄마·아빠한테 물어보자"이다 (`askFlow.ts` blocked). 서툰 발음으로 말한 부적절 단어도 막을지는 목록 확정 때 정한다
