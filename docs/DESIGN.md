# DESIGN.md

## Design Goal
글을 막 배우는 만 5~8세 아이가 혼자서도 쓸 수 있는, 외계인 캐릭터 '모야' 중심의 모바일 웹. 보호자 화면(온보딩·보호자 모드)은 아이 화면과 분리하고 보호자 비밀번호로 잠근다.

- 결정·비교 기준·노드 지도: `planning/prompts/design-v2-2026-10-09.md`
- 화면 목록·버튼 이동표·주소 표: `openspec/changes/apply-hifi-design/design.md`
- 기준 폭 402px(앱 틀 최대 402px). 402px에서 피그마와 일치(위 상태바 62px를 뺀 402×812, 위치 ±1px), 375·390px에서는 가로 넘침·잘림 없음. 상태바·홈 인디케이터는 그리지 않고, 하단 탭바 아래 여백은 기기 안전 영역으로 둔다.

## Visual Tone
- 크림 배경, 라임·보라 포인트, 3D 캐릭터 모야와 표정 변화(듣는 중·생각 중·기쁨·헷갈림)
- 한 화면에 한 가지 행동, 큰 버튼(마이크 118 · 주요 버튼 60 · 카드 114 이상)
- 모야 대사는 말풍선에 보이고 스피커로 다시 듣는다(자동 읽기 + 보조기기 알림)
- 글꼴: Jua(말풍선·제목), NanumSquareRound ExtraBold(하단 탭), Noto Sans KR(본문)
- 주요 색: 크림 `#fdf9ed`, 진한 글자 `#241f48`, 보통 글자 `#6f6a8c`, 라임 `#d2ec7c`, 코랄 `#ff6b5b`, 연보라 선 `#d9d0ff`, 흰 면 `#ffffff`, 보라 `#7b61f8` (전체 토큰은 03_UX_UI_SPEC §5, apply-hifi-design 그룹 1에서 갱신)

## Main Screens
- 온보딩 (`/`, `/login`, `/signup/*`): 1-1 시작 → 1-2 보호자 가입 → 1-3 아이 프로필 → 1-4 음성 동의 → 1-5 비밀번호 → 1-6 마이크 권한(실제 권한 창) → 1-8 아이 모드 시작. 1-0 로그인. 모두 기기 저장 mock
- 모야와 놀기 (`/app`): 2-1 홈 → 2-2 듣는 중 → 2-3 생각 중 → 2-4 확인 질문 → (아니야) 2-5 어디서 들었어? → 2-6 후보 고르기 → 2-9 뜻 알려주기 → 2-10 카드 획득. 2-7 다시 말해줄래, 2-8 물어볼 단어, 2-0 오늘의 미션, 2-13·2-14 미션 성공, E-1·E-2
- 단어 또 보기 (`/app/dictionary`): 3-1 지구 사전, 3-2 카드 상세
- 오늘의 단어 (`/app/today`): 3-3, 3-3a
- 내 정보 (`/app/me`): 3-4 내 정보, 3-5 내 별과 로켓
- 보호자 모드 (`/parent/*`): 5-1 비밀번호 → 5-2 보호자 홈, 5-3 물어볼 단어·단어 알려주기, 5-4 설정(프로필·비밀번호·기록 삭제·동의 철회·로그아웃)
- 베타(만들지 않음): 4-1~4-6 복습·주간 리포트·구독. 베타 표시 항목은 보이기만 한다

## UI Rules
- Use clear button text.
- Use labels for inputs.
- Use semantic headings.
- 글자 없는 아이콘 버튼(스피커, "<", "×", 설정)은 피그마대로 두되 보조기기가 읽을 이름을 단다.
- Avoid random design changes. 값은 피그마 숫자 그대로(눈대중 금지), 화면 글자는 피그마 문구 그대로.
- 피그마에 없는 상태(빈 목록, 입력 오류, 폴백 등)는 만들기 전에 PM에게 확인한다.
- 하단 탭 [모야와 놀기] [단어 또 보기] [내 정보], 헤더의 미션 별 3칸(→ 2-0)과 별 개수(→ 3-5)는 모든 아이 화면에 공통.
- 후보 카드는 한 번 누르면 바로 뜻으로 간다. 스피커는 소리만 낸다.
- '녹음 듣기'와 '내가 말한 소리'는 녹음 대신 인식된 글자를 기기 음성으로 읽는다(음성 원본 저장 안 함).
- 마이크를 쓸 수 없을 때는 글자 입력·예시 버튼 폴백을 보여준다(시연 안정성).
