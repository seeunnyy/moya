## 3. 노션에서 바뀐 점 (폴더 문서 기준)

### 3-1. 기능 구성 — 번호가 바뀌고 4번이 새로 생김

| 노션 | 단계 | 폴더 기존 |
|---|---|---|
| 1. 음성으로 묻기 | MVP | F1 |
| 2. 되묻기로 단어 찾기 | MVP | F2 |
| 3. 단어 카드 | MVP | F3 |
| 4. 보호자 계정과 아이 프로필 | **MVP (신규)** | 없음 |
| 5. 외계인과 반복 학습 (가르쳐주기) | 베타 | F4 |

- 구독: 베타에서 "무료 체험 한도에 도달하면 구독 전환 안내"(무제한 질문·주간 리포트). 해커톤은 "결제는 제공하지 않는다". → 폴더의 "결제·구독 제외"를 "결제: 해커톤 제외 / 구독: 베타"로 고친다.

### 3-2. 보호자 계정·아이 프로필·음성 수집 동의 (신규, 해커톤 범위)

- 노션: 보호자가 가입 → 아이 프로필(별명·연령) 생성 → 음성 수집·보관·활용 동의 → 아이 모드 전환. **동의를 마친 프로필만 음성 질문을 시작한다.** 출력: 아이 프로필, 동의 여부·일시.
- 로드맵 '해커톤(~11월)': "보호자 가입·아이 프로필·음성 수집 동의까지 완성해 모바일 웹 배포".
- BE 담당: "저장(DB), 보호자 계정·아이 프로필·동의 기록 연결".
- 폴더와 충돌: CLAUDE.md Boundaries "complex authentication (MVP는 로그인 없이 시작)", 01 §5·PRD Non-goals "회원가입·복잡한 인증 제외", config.yaml "로그인 없음", 04 §5 "localStorage, 서버 DB·인증은 BE 합류 후".

### 3-3. 아이 모드 / 보호자 모드 분리

- 노션: 아이 모드에는 묻기·단어 카드·복습(베타)만 보인다. **동의·리포트·물어볼 단어·구독·계정 설정은 보호자 확인 후에만** 열린다.
- 노션 화면 흐름: 온보딩(보호자 가입·아이 프로필·음성 동의) → 보호자 홈 → ① 아이 모드: 홈 → 음성 질문 → 되묻기·후보 선택 → 단어 카드 (복습 `베타`) / ② 보호자: 물어볼 단어 · 리포트 `베타` · 구독 안내 `베타` · 계정 설정
- 사용 시나리오 5: "보호자는 자신의 계정에서 연결된 아이의 물어볼 단어와 주간 리포트를 확인한다."
- 폴더와 충돌: 03 S7(아이 단어장)에 물어볼 단어 표시, 진입 흐름 S0 랜딩 → S1, S8 `/parent`는 '자리만(베타)'.

### 3-4. 상황 버튼(맥락 질문)이 노션 MVP에 없다

- 노션 되묻기: "후보 1개면 확인 질문, 여러 개면 후보 2~3개를 들려주고 고르게, 0개면 '물어볼 단어'로 저장." 맥락은 베타: "아이 말의 맥락으로 후보·뜻을 고르는 재순위". 차별점: "발음 패턴과 되묻기로 단어를 유추한다".
- 폴더: FR-05 "어디서 들었어?" 상황 버튼 + 동점 정렬, `WordEntry.contextTags`, `WordCard/PendingWord.heardContext`, QA-02, 05 §5 데모 3단계, CLAUDE.md "핵심 차별점… 상황 맥락으로"·Hackathon Focus "맥락 기반 단어 유추", 리뷰 결정 2. **이미 구현됨(작업 5.4).** → §4 Q1

### 3-5. 묻기: 질문 패턴이 없어도 실패로 끝내지 않음, '발음 단서'

- 노션: "음성인식 → '○○이 뭐야?' 같은 질문 패턴에서 단어 추출. **패턴이 없거나 인식이 불확실해도 실패로 끝내지 않고, 원본 음성의 발음 단서와 함께 후보 추론으로 넘김.**" 출력: 인식 텍스트, 대상 단어, 발음 단서.
- 노션 되묻기: "인식 텍스트가 흔한 다른 단어로 바뀌어도 원본 음성의 발음 단서를 우선 반영."
- 폴더: FR-02 "패턴이 없거나 비어 있으면 E2", QA-06. '발음 단서'의 정의 없음(가장 가까운 것은 FR-01의 STT n-best 후보). → §4 Q4

### 3-6. 되묻기에 답하는 방법

- 노션: 확인 질문은 고정 문장 틀(2~3종) + 단어별 힌트 (예: "저금통 말하는 거야? 돈을 모아 두는 통!"). 후보 카드도 같은 힌트를 읽어 줘 뜻으로 구분하게 한다. **"아이는 '맞아/아니야' 말이나 카드 터치로 선택"**. 동음이의어는 뜻별로 나눠 힌트로 구분.
- 폴더: [응] [아니야] 버튼만. 03 §3 "음성인식을 한 번 더 부르지 않는다"(맥락 질문 기준). → §4 Q5

### 3-7. 실패·대기 처리 (노션 '아이 눈높이 UI 원칙')

- 인식 실패: 모야가 "다시 말해줄래?" → 대답이 없으면 한 번 더 물음 → 그다음 **카드 선택으로 안내**. (폴더 E2: 바로 [다시 말하기]·텍스트 입력·예시 버튼. '카드 선택'이 무엇인지는 노션에 없음 → Open Question)
- 마이크 권한: 그림과 음성으로 안내.
- 네트워크 오류: **1회 자동 재시도 후 [다시 시도] 버튼**. (폴더: 자동 재시도 없음)
- 응답 시간: 녹음이 끝나면 바로 모야가 생각하는 모습, **녹음 종료 후 8초 안에 후보 추론 시작, 후보가 나오면 2초 안에 힌트 음성 시작.** 단계별 응답 시간을 기록해 관리. (폴더 NFR-02: "첫 반응 3초 이내, 잠정")
- 음성 재생이 실패하면 텍스트와 [다시 듣기] 버튼을 보여준다.
- 입력: **"글자 입력 없이 큰 마이크 버튼 하나로 묻는다."** 녹음 중에는 마이크 상태를 크게 보여준다. (폴더 S1·E1·E2: 텍스트 입력 폴백, FR-13) → §4 Q6

### 3-8. 단어 카드

- **"이미 저장된 단어는 중복 카드 없이 질문 횟수만 늘림."** → 폴더 design.md Open Questions의 '중복 카드'는 이것으로 결정됨. `WordCard`에 질문 횟수 필드가 필요하다.
- 후보·단어 카드는 **"큰 글씨 + 그림 + 스피커(다시 듣기) 버튼"**. 폴더 `WordEntry`에 그림 필드가 없다. → §4 Q7

### 3-9. 대사·말투

- 모야도 모르는 단어: **"나도 아직 몰라, 엄마 아빠랑 알아볼게!"** (폴더 S6: "모야도 아직 몰라. 나중에 같이 알아보자")
- 듣는 중에는 귀를 기울이고, 찾는 중에는 고민하는 모습 (외계인 애니메이션 + 짧은 음성 안내).
- 복습(베타): 모야가 모르는 척 물어 아이가 가르치는 느낌. 피드백은 칭찬 위주, '틀렸다'는 직접 표현을 피한다. 1·3·7일 주기, 다음 복습일(물어볼 날)을 정한다.

## 4. 먼저 사용자에게 물을 것

한 메시지로 묻는다. 사용자가 "권장대로"라고 하면 권장안으로, 권장이 없는 질문은 **노션 쪽**을 기본값으로 진행한다.

- **Q1. 상황 버튼(맥락 질문)**
  - A (권장, 노션대로): MVP에서 빼고 베타 '맥락 재순위'로 옮긴다. FR-05를 "후보 2~3개를 힌트와 함께 들려주고 고르게"로 고치고, `contextTags`·`heardContext`는 베타로 표기. 데모 3단계는 "가바가 뭐야? → 가방·가발 힌트 듣고 고르기"로.
  - B: 폴더대로 MVP에 남긴다. (이 경우 노션에도 다시 적어야 함 — 노션 수정은 사용자가 한다)
- **Q2. 보호자 계정(기능 4)을 문서에 어디까지 쓸지**
  - 권장: 행동 요구사항(가입, 아이 프로필, 동의 기록, 보호자 확인, 모드 분리, 보호자용 물어볼 단어)은 MVP로 쓰고, 가입 방식·보호자 확인 방식(비밀번호 재입력, PIN 등)·DB·인증 서비스·카드 저장 위치(localStorage 유지 vs 아이 프로필 기준 서버 저장)는 Open Question(10/19 BE 합류 후 결정)으로 둔다. 심사 시연용 데모 계정을 미리 만들어 두는 것을 05에 (제안)으로 적는다.
  - 함께 확인: 인증·DB 서비스가 "외부 API는 음성인식 하나" 원칙에 걸리는지.
- **Q3. 음성 데이터와 동의 구조**
  - A (권장): 음성 원본은 MVP에서도 저장하지 않는다. 동의를 '음성 인식 처리(필수, 없으면 음성 질문 불가)'와 '서비스 개선 활용(선택)'으로 나누고, 선택 동의 시에도 개선용으로는 인식 텍스트 ↔ 확정 단어 쌍만 남긴다. 동의 철회·기록 삭제는 MVP에서 '요청 경로 안내'까지만.
  - B: 선택 동의 시 음성 원본도 보관한다. (보관 위치·기간·삭제 절차를 새로 정해야 함)
  - 참고: 만 14세 미만 아동의 개인정보 처리에는 법정대리인 동의가 필요하다. 동의 문구는 확정 전에 따로 확인한다.
- **Q4. 질문 패턴이 없을 때와 '발음 단서'**
  - 권장: 인식 결과가 비어 있으면 E2, 패턴만 없으면 인식 텍스트 전체를 대상 단어로 후보 추론에 넘긴다. '발음 단서'는 MVP에서 STT n-best 후보로 정의하고, 녹음 테스트(10/16~22) 뒤 다시 정한다(Open Question).
- **Q5. 확인 질문·후보 고르기에 말로 답하기("맞아/아니야")**
  - A (노션대로): MVP에 넣는다. 말 또는 터치로 답하고, 말 답변 인식에 실패하면 버튼으로. (STT를 한 번 더 부르므로 응답 시간·비용 영향)
  - B: MVP는 터치만, 말 답변은 베타.
- **Q6. 텍스트 입력**
  - 권장: 아이 화면 기본 UI에서는 텍스트 입력을 뺀다(노션 "글자 입력 없이"). 서툰 발음 예시 버튼은 시연·폴백용(E1·E2 또는 시연 모드)으로 남긴다. 텍스트 입력을 개발·시연용으로 남길지 함께 정한다.
- **Q7. 카드 그림**
  - 단어 데이터에 그림 필드를 추가하고 그림 출처(직접 제작, 무료 일러스트, 이모지 등)는 TBD로 둘지, 10/29 단어 데이터 일정에 그림을 포함할지.
- **Q8. 사용성 테스트 기간**: 11/6~11/9 vs 11/6~11/12 (노션 안에서 다름)
- **Q9 (선택).** `.claude/skills/planning-review`·`md-to-openspec`의 '모야 프로젝트 참고 맥락'(맥락 유추 차별점 문구)도 노션에 맞게 고칠지.

## 6. 작성 규칙

- **기존 ID는 번호를 바꾸지 않는다**(코드 주석·테스트·OpenSpec이 참조한다). 없어진 요구사항은 행을 지우지 말고 "삭제 (2026-10-04, 노션 반영: <사유>)" 또는 "베타로 이동"으로 표시한다.
- 새 ID는 지금 마지막 번호 다음부터: FR-14~, NFR-10~, QA-13~, 화면 S9~ / E3~.
- 기능 번호는 노션(1~6)을 따르고, 02 맨 위에 "기능 번호 변경: 구 F4 → 5, 구 F5 → 6, 4 신규(보호자 계정과 아이 프로필)" 한 줄을 둔다.
- 단계 표기는 MVP / 베타. 노션의 `베타` 표시를 그대로 옮긴다.
- 최종 수정일은 2026-10-04, 문서 상태는 Draft 유지.
- 노션 문장을 우선 쓰고, 짧고 쉬운 한국어로 쓴다. 노션에 없는 수치(예: PIN 자릿수, 무료 체험 한도)는 쓰지 않거나 "(제안)"으로 표시한다.
