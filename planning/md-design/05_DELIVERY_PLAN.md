## 2. Today
### 목표
외부 API 없이 "묻기 → 되묻기 → 카드 저장" 흐름을 처음부터 끝까지 한 번 관통한다. 마이크 대신 텍스트 입력을 쓴다.

### 할 것
1. 공통 타입 (04 §3)
2. 되묻기 순수 로직 (04 §2): 자모 분해, 자모 편집거리, 역규칙 적용, 후보 분기(1개 / 여러 개 / 0개), 대상 단어 추출
3. 초기 역규칙 3개. 10/16~22 녹음 테스트로 보정할 가설이다.
   - R1. ㅅ·ㅆ ↔ ㄷ·ㄸ 대치 (초성)
   - R2. 받침 생략. 별도 변형 없이 편집거리의 종성 삽입(거리 1)으로 처리한다 (잠정)
   - R3. 된소리·거센소리 ↔ 예사소리 (ㄱ·ㄲ·ㅋ / ㄷ·ㄸ·ㅌ / ㅂ·ㅃ·ㅍ / ㅈ·ㅉ·ㅊ)
4. mock 단어 데이터 10개 (§3). 파일 안에 mock이고 검수 전임을 명시한다.
5. /app 흐름: 텍스트 입력(STT mock 대신) → S3 확인 / S4 고르기 / S6 물어볼 단어 → S5 설명(mock 데이터) → localStorage 저장
   - S4의 맥락 질문은 상황 버튼으로 받는다. 거리가 같은 후보 중 그 상황 태그를 가진 단어를 앞에 두고, 고른 상황을 `heardContext`로 저장한다.
   - 확인 질문은 고정 문장 틀 1종 + 힌트로 시작한다 (2~3종은 이후).
6. /app/cards: 저장한 카드와 물어볼 단어 목록

### 안 할 것
- 실제 음성인식 연동, 마이크 녹음, 음성 재생(speechSynthesis)
- LLM 재순위, 실시간 설명 생성 (베타)
- 예시 단어 버튼과 저장·전송 고지 (1차 배포 전에 한다. QA-11, QA-12)
- 모야 애니메이션. 정적인 자리와 상태 글자로 대신한다.
- 스타일 다듬기, 랜딩(S0), F4·F5
- 단위 테스트 도구 설치. 오늘은 수동 QA만 한다. 도구 선정은 TBD.

## 5. Demo Scenario
발표 시연은 이 순서로 고정한다. 마이크가 실패하면 같은 문장을 예시 단어 버튼(FR-13)으로 넣는다. 단어는 지금 mock 기준이며, 검수 데이터로 바뀌면 같은 패턴(R1 대치, 후보 여러 개, 후보 없음)의 단어로 교체한다.

1. S0 → [모야 만나러 가기] → S1
2. [두박이 뭐야?] → S3 "수박 말하는 거야? 여름에 먹는 크고 둥근 과일!" → [응] → S5 설명 + 저장 표시 (발음 역규칙)
3. [가바가 뭐야?] → S4 "어디서 들었어?" → [TV] → 가발이 첫 번째 후보 → [이거야!] → S5 (맥락 단서)
4. [뿌잉뿌잉이 뭐야?] → S6 물어볼 단어
5. [단어장] → S7에서 수박·가발 카드와 물어볼 단어 확인

## 6. Word Data Checklist
검수된 단어 데이터(04 §2)의 항목마다 확인한다.
- [ ] `dictDefinition`을 출처 사전과 대조했다
- [ ] `kidExplanation`과 `example`이 사전 뜻 범위 안에 있다
- [ ] 설명은 두 문장 이하이고, 표제어보다 어려운 단어를 쓰지 않았다 (기준 잠정)
- [ ] 힌트만 듣고도 거리가 가까운 다른 단어와 구분된다
- [ ] 동음이의어는 `senseId`로 나눴고, 힌트가 서로 다르다
- [ ] `contextTags`가 1개 이상 있다
- [ ] 아이에게 부적절한 내용이 없다
