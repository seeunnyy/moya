## 6. 실기기 확인 (휴대폰으로 개발 서버 접속)
마이크는 **https 주소나 localhost에서만** 쓸 수 있다(브라우저 보안 규칙). 그래서 방법에 따라 확인할 수 있는 것이 다르다.

| 방법 | 기기 | 마이크(1-6 → 1-7, 실제 음성) | 화면·폴백·E-2 |
|---|---|---|---|
| A. 같은 와이파이 + PC 주소 | Android·iPhone | 안 됨(http라 마이크 버튼이 바로 E-2) | 됨 |
| B. USB 케이블 + 포트 전달 | Android(Chrome) | 됨 | 됨 |
| C. https 주소 | Android·iPhone | 됨 | 됨 — 1차 배포 URL이 생긴 뒤. 그 전에 터널 도구를 쓰려면 새 도구라 먼저 확인받는다 |

**A. 같은 와이파이로 열기 (화면·폴백 데모)**
1. PC와 휴대폰을 **같은 와이파이**에 연결한다.
2. PC의 VS Code 터미널(또는 명령 프롬프트)에서 `npm run dev`를 실행한다. 이미 켜져 있으면 그대로 둔다.
3. PC 주소를 찾는다: 터미널에 `- Network: http://192.168.0.12:3000` 같은 줄이 보이면 그 주소. 안 보이면 명령 프롬프트에서 `ipconfig` → "IPv4 주소" 숫자 + `:3000`.
4. 휴대폰 브라우저 주소창에 `http://그주소:3000` (예: `http://192.168.0.12:3000`)을 입력한다.
5. 안 열리면: ① Windows에서 "Node.js가 네트워크에 접근하도록 허용할까요?" 창이 떴으면 **개인 네트워크 허용** ② 학교·회사 와이파이는 기기끼리 연결을 막기도 하니 휴대폰 핫스팟에 PC를 연결해 다시 ③ 휴대폰이 데이터(LTE)로 붙어 있지 않은지 확인.
6. 2-1에서 마이크를 누르면 바로 E-2가 나온다(정상). [글자로 물어볼래]로 폴백 데모를 한다.

**B. Android 휴대폰 + USB 케이블 (마이크 흐름)**
1. 휴대폰 개발자 옵션 켜기: 설정 → 휴대전화 정보 → 소프트웨어 정보 → **빌드번호를 7번** 누른다.
2. 설정 → 개발자 옵션 → **USB 디버깅** 켜기 → USB로 PC에 연결 → 휴대폰에 뜨는 "USB 디버깅을 허용할까요?"에서 허용.
3. PC Chrome 주소창에 `chrome://inspect/#devices` → 휴대폰 이름이 보이면 **Port forwarding…** → Port `3000`, IP address and port `localhost:3000` → **Enable port forwarding** 체크 → Done.
4. 휴대폰 Chrome 주소창에 `http://localhost:3000` 입력 (localhost라 마이크가 된다).
5. 1-6 → 1-7 확인: `/dev/seed` → [처음 상태로 되돌리기] → 가입을 끝까지 → 1-6 [마이크 켜기] → 휴대폰의 진짜 권한 창. 이미 허용했다면 주소창 왼쪽 아이콘 → 권한 → 마이크 **초기화** 후 다시.
6. E-2 확인: 같은 곳에서 마이크를 **차단** → 새로고침 → 2-1 마이크 → E-2. 끝나면 다시 허용.
7. 지금은 mock STT라 무슨 말을 해도 §3의 차례대로 결과가 나온다. 실제 인식은 STT 확정 뒤(12.1).

**C. iPhone(Safari)에서 마이크**: Safari는 https 주소가 있어야 마이크를 쓸 수 있다. 1차 배포(11/5 전) URL에서 확인한다.
