## 판정
**보완 후 진행.** 오늘 범위(05 §2: 텍스트 입력 + mock 데이터로 묻기 → 되묻기 → 카드 저장)는 인수조건과 QA가 갖춰져 있어 지금 구현해도 된다. 다만 실제 음성인식 연동과 시연 전에는 아래 [필수] 5개를 정해야 한다. 특히 1번(음성인식 결과가 역규칙의 전제와 맞는지)이 틀리면 되묻기 로직 전체가 흔들린다.

## [필수] 구현 전에 정할 것

1. **음성인식이 '틀린 발음 그대로' 글자로 돌려준다는 전제가 검증되지 않았다** — 근거: 04 §2 `rules.ts`·`candidates.ts`, 05 §2-3 "녹음 테스트로 보정할 가설", 04 §1 "STT 서비스 선정은 TBD"
   - 문제: 역규칙과 거리 비교는 STT가 "두박"처럼 아이 발음을 그대로 적어 준다고 가정한다. 범용 STT는 언어 모델로 실제 단어("두부" 등)나 전혀 다른 문장으로 교정해 돌려주는 경향이 있다 (추정). 그러면 역규칙이 적용될 입력 자체가 생기지 않는다.
   - 수정안: STT 후보 2~3개를 10/16 녹음 테스트 **전에** 고르고, 테스트에서 "발음 그대로 적힘 / 다른 실제 단어로 교정됨 / 인식 실패" 비율을 후보별로 잰다. 선정 기준에 ① 여러 인식 후보(n-best) 제공 여부 ② 한국어 아동 발화 정확도 ③ 데이터 보관 정책(→ 5번)을 넣는다. 교정 성향이 강하면, n-best 후보 전부를 거리 비교의 입력으로 쓰는 방식을 04에 대안으로 적어 둔다.

2. **피칭 차별점('맥락 기반 단어 유추')과 MVP 동작이 다르고, 맥락 질문에 답하는 방법이 없다** — 근거: CLAUDE.md "Hackathon Focus", 01 §4 차별점, 02 FR-05 "맥락으로 재순위하는 기능은 베타", 03 S4, 05 QA-02 "맥락 질문에 'TV에서 들었어'"
   - 문제: 발표는 '맥락으로 유추'를 내세우는데, MVP에서 맥락은 기록만 하고 후보 순서는 발음 거리로만 정한다. 시연에서 차별점이 화면에 보이지 않는다. 또 S4의 맥락 질문에 아이가 말로 답하는지(STT를 한 번 더 호출), 버튼으로 답하는지 정의돼 있지 않다.
   - 수정안: 아래 열린 질문 Q1에서 A나 B를 고른다. 어느 쪽이든 03 S4에 답하는 방법을 적는다.

3. **검수된 단어 데이터 50~100개의 담당, 형식, 검수 절차가 없다** — 근거: 04 §2 "단어 선정 기준과 출처는 TBD", 05 §1 "10/29 검수된 단어 데이터 50~100개 완성", 노션 §8(BE 담당 예정, 모집 중)
   - 문제: 해커톤의 쉬운 설명, 예문, 힌트, 동음이의어 구분이 모두 이 데이터에 달려 있다(FR-04·05·07). 그런데 BE가 아직 없고 마감까지 4주다.
   - 수정안: 담당자를 정한다(BE가 합류하기 전에는 PM이 맡는다). 04 §3의 `WordEntry` 형식으로 녹음 테스트 단어 10개를 먼저 만들어 mock 데이터를 대체한다. 검수 체크리스트를 05에 추가한다: 사전 뜻 대조, 설명 길이, 설명 안에 어려운 단어가 없는지, 힌트로 비슷한 단어끼리 구분되는지.

4. **시연 모드가 정의돼 있지 않다** — 근거: CLAUDE.md "시연 안정성 우선", 02 FR-13, 05 §2 "예시 단어 폴백 버튼은 오늘 안 함"
   - 문제: 발표장 소음과 네트워크 상태 때문에 실시간 마이크 시연은 실패하기 쉽다. FR-13의 '예시 단어'가 정확한 단어만 넣는다면, 핵심 장면(엉성하게 물어도 맞춰주는 순간)을 재현할 수 없다.
   - 수정안: 예시 단어 버튼이 **엉성한 발음**을 입력하게 한다. 예: [두박이 뭐야?], [가바가 뭐야?]. 아래 데모 시나리오를 05에 고정해 둔다. 마이크가 실패해도 같은 장면을 버튼으로 보여줄 수 있다.

5. **아이 음성이 외부 STT로 전송된다는 고지와 보호자 동의가 빠져 있다** — 근거: 02 NFR-04 "보호자 동의 절차는 TBD", NFR-09, 03 §3 "저장 고지", 05 §1 사용성 테스트 11/6~11/12
   - 문제: 우리가 음성을 저장하지 않아도 STT 제공사로는 전송된다. 실제 아이가 참여하는 사용성 테스트가 11/6에 있는데, 동의 절차와 고지 문구가 TBD다.
   - 수정안: NFR-09 고지 문구에 "목소리는 글자로 바꾸는 데만 쓰고 저장하지 않아요"처럼 외부 전송 사실을 넣는다. 보호자 동의서는 녹음 테스트(10/16)용 양식을 재사용해 사용성 테스트 전까지 확정한다. STT 제공사의 데이터 보관 정책을 1번 선정 기준에 넣는다.

## [권장] 정하면 좋은 것

1. **세계관과 학습 구조가 대사에서 충돌할 수 있다** — 근거: 01 §1 "지구 말을 배워가는 외계인", 03 S5 설명, S6 "모야도 아직 몰라"
   - 문제: 지구 말을 배우는 중인 모야가 단어 뜻을 척척 설명하면 설정이 어긋난다.
   - 수정안: 설명의 주체를 '지구 번역기'로 둔다. 예: "번역기로 찾아봤어! 수박은 여름에 먹는 크고 둥근 과일이래." S6은 "번역기에도 없네. 나중에 같이 알아보자"로 바꾼다. 모야는 함께 배우는 친구로 남기고, 이 대사 규칙을 03 §1 문장 틀에 적는다.

2. **'들은 상황'이 후보가 여러 개일 때만 수집된다** — 근거: 02 FR-09 카드 필드, FR-05, 04 §3 `heardContext?`
   - 문제: 확인 질문 경로(S3)에서는 들은 상황을 묻지 않아 카드마다 필드가 들쭉날쭉하다.
   - 수정안: (A) 선택 필드로 확정하고 S7에서 비어 있으면 숨긴다. (B) 설명이 끝난 뒤 "어디서 들었어?"를 한 번 묻는다. 권장은 A다. MVP 흐름이 짧아진다.

3. **대상 단어 추출 패턴이 좁다** — 근거: 02 FR-02, 05 QA-06
   - 문제: STT가 "머야", "뭐예요", "뭔데"로 적거나, 아이가 단어만 말하면 모두 E2로 빠진다.
   - 수정안: 패턴에 "머야", "뭐예요", "뭐에요", "뭔데"를 추가한다. 패턴이 없어도 입력이 짧으면(예: 4음절 이하, 제안) 입력 전체를 대상 단어로 본다. '이'로 끝나는 단어(고양이)의 예외 처리와 함께 02 FR-02 인식 패턴에 명시한다.

4. **정확히 말해도 비슷한 단어 때문에 고르기 화면으로 간다** — 근거: 05 §4 참고 "가방이 뭐야?"
   - 수정안: 거리 0인 후보가 하나뿐이면 확인 질문(S3)으로 보낸다(제안). 동음이의어처럼 거리 0이 여러 개일 때만 S4로 간다. 04 §2 `candidates.ts` 분기 규칙에 적는다.

5. **부적절 단어 처리의 MVP 최소 버전이 없다** — 근거: 02 NFR-06 "판별 기준 TBD", CLAUDE.md "Moya Response Rules"
   - 문제: 검수 데이터에 없는 단어는 S6 '물어볼 단어'로 저장된다. 그래서 욕설도 단어장과 부모 화면에 그대로 남을 수 있다.
   - 수정안: MVP에서는 금칙어 목록(src/data) 확인만 한다. 걸리면 "엄마·아빠한테 물어보자"를 보여주고 저장하지 않는다. 판별 기준을 정교하게 만드는 건 베타로 미룬다.

6. **추적표에 비어 있는 행이 있다** — 근거: 02 §4
   - 수정안: NFR-02·03·05·06·09 행을 추가한다. MVP인 FR-08(음성 출력)과 NFR-09(저장 고지)에 QA 항목을 만든다. 오늘 범위가 아니면 "1차 배포 전 QA"로 표시한다.

7. **확인할 수 없는 표현이 있다** — 근거: 01·02의 "아이 눈높이", 03 §3 "말이 끝나면 자동으로 멈춘다"
   - 수정안:
     - 쉬운 설명 기준: 한 문장 25자 이내, 두 문장 이하, 설명 안에 표제어보다 어려운 단어를 쓰지 않는다 (제안).
     - 자동 종료 기준: 무음 1.5초 또는 최대 녹음 8초 (제안). 둘 다 사용성 테스트로 확정한다.

## 유지할 결정
- 해커톤 외부 API는 음성인식 하나. 설명과 힌트는 검수된 데이터만 쓴다.
- 되묻기 로직은 외부 의존 없는 순수 함수다.
- 아이 음성 원본은 저장하지 않는다. MVP 저장소는 localStorage다.
- F4·F5는 베타다.
- 화면은 자동으로 넘어가지 않는다. 모든 대사는 글자와 음성으로 함께 나온다.
